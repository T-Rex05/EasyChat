# 系统化调试

**核心原则：先找根因，再修复。修症状 = 失败。**

## 四阶段

### 1. 根因调查

- 仔细读错误信息和堆栈
- 稳定复现（触发步骤、频率）
- 检查最近改动（git diff）
- 多组件系统：每层加诊断日志，找到断裂点

### 2. 模式分析

- 找同类正常工作的代码对比
- 列出所有差异点（别跳过"看起来不重要"的）
- 理解依赖和环境差异

### 3. 假设验证

- 一次只改一个变量
- 验证通过 → 进入实现；失败 → 新假设
- ≥3 次失败 → 停下来质疑架构设计，不要继续修补

### 4. 实现修复

- 修复根因，不修症状
- 单次单改动，不夹带重构
- 验证修复有效 + 无回归

## 红旗信号

想到"快速修一下，后面再查"、"试试改 X 看行不行"、"我不太理解但可能有用" → **退回阶段 1**。
