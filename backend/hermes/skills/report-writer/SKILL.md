# /report-writer — 通用报告生成器

从零散素材生成结构清晰、格式规范的专业报告（Markdown 格式）。

## 触发条件

用户提到：写报告、生成报告、整理成报告、周报、月报、分析报告、会议纪要、调研报告、数据报告、总结报告。

## 工作流

### 1. 收集素材
- 获取用户提供的所有输入：文本、数据、文件、链接、截图
- 如果输入不足，主动询问关键信息：主题、受众、时间范围、核心要点
- 宁可多问一句，不猜测关键数据

### 2. 确定报告类型
根据用户描述自动识别，或让用户确认：

| 类型 | 特征 | 结构模板 |
|------|------|----------|
| 周报/月报 | 时间段、进展、计划 | 概述 → 进展 → 风险 → 下期计划 |
| 分析报告 | 问题/现象、数据支撑 | 背景 → 分析 → 方案对比 → 结论建议 |
| 会议纪要 | 参会人、讨论、决议 | 基本信息 → 议题讨论 → 决议 → 行动项 |
| 调研报告 | 多源信息、对比 | 背景目的 → 调研方法 → 发现 → 结论 |
| 数据报告 | 数据来源、指标 | 概览 → 指标解读 → 趋势分析 → 建议 |

### 3. 生成报告
- 关键信息务必准确，不确定的标注 `[待确认]`
- 数据类内容优先用表格呈现
- 结论和建议要具体、可执行，避免空话

### 4. 输出与迭代
- 默认输出完整 Markdown 到对话中
- 询问用户是否需要保存为文件、调整格式、补充内容
- 支持多轮修改直到用户满意

## 质量标准

- **准确** — 不编造数据，不确定的明确标注
- **结构化** — 层级清晰，标题、表格、列表合理使用
- **可执行** — 行动项有负责人和截止时间
- **精炼** — 删除冗余，每句话有信息量

## 注意事项

- 公司/项目名称等敏感信息不编造，用 `[填写]` 占位
- 报告始终用中文，除非用户指定其他语言
- 技术报告中的代码块标注语言类型
