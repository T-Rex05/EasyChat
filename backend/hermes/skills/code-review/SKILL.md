# 代码审查

四维度系统化代码审查方法论。

## 何时使用

- 用户说 "审查这段代码"
- 用户贴出代码片段请求 feedback
- PR 审查场景

## 审查维度（按优先级）

### 1. 安全性 🔴
- SQL 注入：是否使用参数化查询
- XSS：用户输入是否正确转义
- 硬编码密钥：是否有明文 API Key/密码
- 路径遍历：文件操作是否有路径校验
- 权限绕过：是否有越权风险

### 2. 性能 🟡
- N+1 查询：循环内是否有重复数据库调用
- 内存泄漏：未关闭的连接/文件句柄
- 不必要的计算：可否缓存或延迟计算
- 索引缺失：查询条件是否有对应索引

### 3. 可读性 🟢
- 命名：变量/函数名是否自解释
- 注释：复杂逻辑是否有注释说明
- 结构：是否遵循单一职责原则
- 魔法数字：是否替换为命名常量

### 4. 最佳实践 🔵
- 错误处理：是否正确处理异常
- 日志：关键路径是否有日志
- 测试：核心逻辑是否有测试覆盖
- DRY：是否有重复代码

## 输出格式

```
## 代码审查报告

### 问题清单
| # | 严重度 | 类型 | 位置 | 问题 | 建议 |
|---|--------|------|------|------|------|
| 1 | 🔴 高  | 安全 | L42 | SQL 拼接 | 改用参数化查询 |

### 改进建议
1. ...
2. ...

### 总体评价
✅ 优点 / ⚠️ 需改进
```

## 注意事项

- 先讲优点再讲问题
- 每个问题附带具体的修复代码示例
- 区分 "必须修复" 和 "建议改进"
