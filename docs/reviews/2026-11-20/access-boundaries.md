# EasyChat 后端权限核对

核对从应用工厂实际注册的 HTTP 接口、微信监听和已经接线的服务入口出发。身份以当前账号状态为准，动作按有效权限判定，个人资源还要校验所有者。管理者可以跨用户的范围以各模块服务为准。[路由装配](../../../backend/app.py)

| 范围 | 核对结果 |
|---|---|
| 登录、用户、角色和权限变更 | 登录和令牌验证按数据库账号状态拒绝禁用用户。修复通用授权函数对旧身份快照仍返回 true 的问题。修改用户、角色和权限覆盖使用 `system.manage`，涉及拥有者的身份和状态另有保护。 |
| 聊天、收件箱和基础偏好 | 修复聊天历史和收件箱改写的撤权缺口，增加基础偏好的动作闸。新建聊天先授权，订阅、运行状态及历史投影再校验权限与归属。 |
| 技能与进化 | 修复个人技能详情、版本、导入和运行时撤权检查。普通用户只读取本人私有技能，跨用户查看需 `skill.manage`。进化经验和回滚经各自的服务授权。 |
| 超级代理 | 普通查看者限本人任务。跨用户筛选需 `superagent.view` 和 `superagent.manage`。可筛选账号需要已启用且具备有效查看权限。任务事件、报告和验收证据使用同一任务权限闸。 |
| 渠道与投递 | 管理端通过 `system.manage` 管理渠道。微信入站根据机器人账号和发送人识别绑定。禁用固定回执走这一入站身份，普通投递校验保持原有范围。投递状态从当前账号读取。 |
| 文件、账单、提醒和记忆 | 文件按动作权限及本人范围检查，跨用户范围经管理权限。账单按动作和账本所有者检查。提醒跨用户操作还需 `system.manage`。记忆读取和修改分别检查相应权限。 |
| 模型、邮箱、MCP 和用量 | 平台配置接口使用 `system.config`。个人邮箱、用量明细各按登录身份限制，用量跨用户查询另需 `trace.manage`。 |

权限回归使用临时 SQLite、ASGI 和模拟微信传输，验证撤权、停用和多个用户的隔离。页面截图使用合成数据。真实微信网络收发需在已绑定并运行监听的环境验证。

原有兼容注册接口仍开放。网页登录页移除了自助注册入口，管理员新建用户使用独立权限接口。
