# 微信记忆与会话角色交付评审

## 草稿范围

本地分支为 `codex/wechat-memory-personas`，基线为 `03b41ee`。原工作区 `feature/permission-remediation` 含有未提交修改，其中包括微信偏好快速保存、权限和前端外壳改造。集成时应按功能检查两边改动，优先复验微信入站、聊天历史、角色选择和权限组合。

| 场景 | 行为和复验位置 |
| --- | --- |
| 网页管理 | 记忆页提供范围过滤、列表、按类型或标签分组的星图、来源、修订和遗忘。搜索和模拟召回分别使用列表和召回接口。对话页可新建、编辑、归档角色，并以选定角色开启独立会话。 |
| 会话和记忆边界 | `tests/contracts/test_persona_sessions.py` 检查 Web 与微信会话路由和入队快照。`tests/contracts/test_web_chat.py` 用实际 dispatcher 请求检查私有记忆、共享撤销、版本和历史投影。 |
| 微信 | `/角色` 或 `/角色 编辑`，`/记忆 mem_…`，`/纠正 mem_…@2 新内容`，`/本轮记忆`。当前部署配置没有公开 Web 基址，`/星图` 返回网页菜单路径。 |
| 旧数据和遗忘 | `tests/storage/test_migration_0014.py` 和 `tests/storage/test_migration_0029.py` 用旧版 SQLite 副本检查追加迁移。`tests/memory/test_forgetting.py` 检查记忆派生文本和重提取保护。 |
| 外发保护 | `tests/delivery/test_delivery.py` 使用真实 SQLite 和替身传输检查微信换绑及权限撤回。队列租约携带原 owner，每个分块外呼前校验当前绑定。对话和记忆确认分别复核现行权限，定时提醒按原能力处理。 |

旧会话和记忆通过空 `persona_id` 保留在默认角色。新增角色的召回使用同一 owner 下角色私有和主动共享的记录。取消共享保留原归属。角色归档后阻止新运行和额外提取，已入队请求保留当时的自定义角色设定。默认角色继续按原用户档案渲染。

每轮最多三条召回引用保存在 `runs.memory_context_refs`，使用有序的 ID 和版本数组。保存在运行行能直接沿用现有 owner 和会话边界，也避免新表的额外写入。读取时重新检查记忆状态和共享范围。星图基于类型、标签和已有替代关系展示已加载的记录。每次列表查询最多加载 200 条，可按范围和关键词缩小结果。Hermes 仍通过既有运行时接口接收角色和记忆上下文。

## 受保护路径与发布复核

本地评审涉及追加迁移 `0027`、`0028`、`0029`，记忆和投递公共契约，以及微信外发边界。应人工复核数据库迁移和回滚范围、现存队列与绑定核对，以及两工作区的接口差异，再合入或发布。独立代码评审复现并修正了旧导航重放覆盖新角色、撤权后重发缓存回复，以及升级后仍待发的旧记忆摘录等问题。

1. 在独立环境用脱敏数据库副本核对待迁移消息的处理数量，验证默认角色可访问原记忆并核对旧会话来源。迁移前积压且没有可验证归属的消息需要人工按业务判断是否重发。
2. 用测试号验证微信扫码、明确记忆修订、A→B→A 切换、账号换绑时队列拒绝，以及分别连接 Web 与微信后继续同一角色各自的会话。检查渠道接口实际状态和返回结果。
3. 用现有 Hermes 配置验证连续多轮、旧会话打开、取消后续聊、跨角色历史隔离和记忆命令。浏览器本地测试使用合成 API 数据，后端契约使用真实 SQLite 和替身模型及微信传输。
4. 回滚应先暂停入站及外发队列并备份数据库。旧代码按 owner 检索记忆，会忽略新角色和共享字段。需要回滚运行代码时使用相匹配的迁移前副本，并另行评估迁移后数据的处理。

记忆遗忘作用于记忆域正文、修订、来源摘录、相关派生字段和提取阻止规则。仍在排队或等重试的匹配确认会取消，待发分块原文会清理。原始会话、已经渲染为对话、正在外发或已经送出的确认，以及历史备份遵循各自的留存规则。

本地重放可恢复已提交的修订。平台再次投递同一事件时，通过当前授权和可见性检查后可以重拿确认。只有本地重放时，可发 `/记忆 <ID>` 核对现行版本。
