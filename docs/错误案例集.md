# EasyChat 错误案例集

这里收录以后排查、设计或评审时值得重看的错误。新增案例按日期倒序放置，给出能检索的标题，并写清现象、根因、处理和验证方法。根因仍在调查时标为「待验证」；同一根因再次出现时，在原条目补充触发条件或遗漏的入口。

## 2026-11-20 · 资源归属正确，动作权限撤销后仍可读写

- **现象**　撤销 `chat.use` 后，账号仍能用旧令牌读本人聊天历史、修改收件箱。技能也有只校验资源归属的读取分支。
- **根因**　部分服务入口检查了会话或条目的所有者，却没有检查当前动作权限。仅检查提交或列表入口时，详情、修改和后台读取仍可能遗漏授权。
- **修复**　服务层同时执行动作权限与资源归属检查。聊天先校验再创建会话，禁用身份快照在通用动作校验中失效，技能撤权后停止注入运行时。
- **回归**　在真实临时 SQLite 中保存记录，撤销原权限后复用原令牌或保存过的身份快照，验证禁止读取、改写和新建。见 [聊天测试](../tests/contracts/test_web_chat.py)、[动作撤权测试](../tests/access/test_action_revocation.py) 和 [禁用缓存测试](../tests/access/test_cache_invalidation.py)。

## 2026-11-19 · 后端健康检查通过，聊天历史仍显示为空

- **现象**　`/readyz` 和登录可用，聊天历史页却显示空列表，浏览器记录「模块未就绪: assistant」。数据库仍有活跃会话。
- **根因**　本地启动漏了 `EASYCHAT_HERMES_ENABLED`。聊天接口依赖 Assistant 装配，而健康检查反映进程是否完成启动。重启后，旧令牌还会因为进程签名密钥变化收到 401。哈希路由的页面路径可以是 `/login`，实际路由仍是 `#/chat`。
- **处理**　用完整的本地配置启动，检查已登录请求的模块状态和历史接口。前端收到 401 时按哈希判断是否已经在登录页。
- **回归**　认证后读取 `/api/history` 并确认已有会话。前端回归从 `/login#/chat` 模拟 401，验证清理令牌并跳转登录路由。见 [启动装配](../backend/bootstrap.py) 和 [聊天回归测试](../agent_frontend/tests/chat-sse-recovery.test.mjs)。

## 2026-11-19 · PDF 技能激活成功，模型仍读不到附件正文

- **现象**　PDF 上传返回 200，已激活的技能进入模型上下文。用真实 GLM 验收时，模型仍无法读出合成 PDF 正文里的核验编号。
- **根因**　普通聊天的附件上下文包含文件名、类型和附件 ID。技能提供处理指引，打开文件仍依赖当前会话的工具或应用侧提取。
- **验证方法**　把模板导入、库操作和对话入口分别验收。用只出现在 PDF 正文中的随机编号作为断言，避免从文件名或用户消息猜中。模板目录已标注会话工具的依赖。见 [附件上下文构建](../backend/modules/assistant/dispatcher.py) 和 [技能模板](../backend/modules/skills/templates.py)。

## 2026-11-19 · 用量账本的业务来源无法区分 Web 和微信

- **现象**　同一用户经 Web 和微信发起聊天，全局用量都显示为 `chat`，最近调用的会话摘要也没有渠道。
- **根因**　`llm_calls.source` 用于区分聊天、记忆和调度等业务。会话的起始渠道在 `sessions.source`，单次交互的渠道在 `runs.source`。从 Web 继续微信会话时，这两个渠道值可以不同。
- **修复**　按用户和会话聚合用量，会话摘要和调用明细各自读取对应的渠道。查不到渠道的历史调用显示「来源未知」。
- **回归**　构造从 Web 继续微信会话的样本，断言会话仍标记为微信、该次调用标记为 Web。验证不同用户的统计独立，以及撤销管理权限后全局接口返回 403。见 [分组和权限测试](../tests/usage/test_call_groups.py)。

## 2026-11-19 · 普通聊天读到了服务端仓库上下文

- **现象**　在全新普通会话发送 `hello`，真实模型偶尔主动提到服务端仓库正在开发的分支。另起会话有时能得到普通问候，单看回复无法判断隔离是否生效。
- **架构原因**　普通聊天与编码任务共用 Hermes。运行时可以根据工作目录发现项目指令和 Git 信息。服务进程从 EasyChat 仓库启动时，进程目录就成了普通用户没有选择过的上下文来源。
- **修复**　普通聊天关闭项目指令发现和宿主环境提示，恢复会话时校验缓存提示的来源。编码任务则把提示构建和工具执行绑定到同一任务工作区。
- **验证**　用真实 GLM 发送 `hello`，在出站请求中检查系统提示，未发现服务端仓库路径、当前分支或仓库指令标记。回归测试在同一进程交替运行普通与编码会话，断言只有编码会话读到了其任务目录中的测试指令和 Git 分支。参见 [Hermes 运行时](../backend/runtime/hermes/) 和 [运行时契约测试](../tests/contracts/test_runtime.py)。

## 2026-11-19 · 一句问候出现几十个“步骤”

- **现象**　模型最后给出了正常问候，聊天气泡却先逐词显示了几十个“步骤”，即使这一轮没有调用工具。
- **根因**　流式接口把逐片到达的模型推理内容当成执行步骤。分片由传输决定，一个词或标点都可能触发一个编号。
- **修复**　在聊天事件边界过滤推理分片，保留最终答复和真实工具事件。前端重放旧事件时也忽略历史 `thinking_step`。
- **回归**　发送无需工具的问题，应只看到回答；执行真实工具时仍应看到工具名；回放旧流不能恢复推理原文。见 [聊天分发](../backend/modules/assistant/dispatcher.py)、[Web 聊天测试](../tests/contracts/test_web_chat.py) 和 [前端流恢复测试](../agent_frontend/tests/chat-sse-recovery.test.mjs)。

## 2026-11-17 · 微信账单笔数被解析为金额

- **现象**　类似 `支出：385笔，共23708.48元` 的摘要被解析成 385 元，上传后触发控制总额与明细不符。
- **根因**　解析器把类别后的第一个数字当作金额。账单摘要里「笔」与「元」可以出现在同一行，金额还可能缺省。
- **修复**　分别识别笔数和金额，并将金额换算为整数分。只有笔数时保留金额未知，让后续核验区分缺值与零。
- **回归**　从 CSV、XLSX 两种真实文件入口读取合成样本，断言金额为 2,370,848 分；另测只有笔数和带逗号的摘要。见 [账单解析回归测试](../tests/ledger/test_parsers.py)。
